# Operating Rules

> 견적 숫자는 실제 돈에 쓰인다. node_trade의 "실거래 안전 규칙"에 해당하는 문서.
> 규칙 번호는 고정한다 — 새 규칙은 뒤에 추가하고, 폐기 시 번호를 지우지 말고 "폐기(날짜, 사유)"로 표시한다.
> 사고에서 나온 규칙은 `incident-log.md`의 해당 항목을 근거로 링크한다.

## 규칙 1. 추적성 — 근거 없는 숫자는 없다

- 수량 행: 근거 도면 파일 + 레이어 + 엔티티 handle 목록 + 산출식.
- 단가 행: 출처 기관·자료명 + 기준일 + URL/문서 위치 + 부가세 포함 여부.
- 근거를 못 붙이면 숫자를 넣지 않는다.

## 규칙 2. 모르면 표시한다 — UNMAPPED / UNPRICED / ESTIMATED / STALE

| 표시 | 의미 | 합계 처리 |
|---|---|---|
| `UNMAPPED` | 도면 객체를 품목으로 매핑 못 함 | 수량표 하단 별도 목록 |
| `UNPRICED` | 단가 출처 못 찾음 | 합계에서 제외, "미확인 N품목" 명시 |
| `ESTIMATED` | 요청에 의해 추정한 단가 | 별도 소계, Gate 3에서 CEO 판정 |
| `STALE` | 단가 기준일 1년 초과(노임은 해당 반기 아님) | 포함하되 경고 |

조용히 버리거나 0으로 채우는 것은 금지.

## 규칙 3. 단위 먼저

- 파싱 첫 단계에서 도면 단위(`$INSUNITS`)·축척·공간(Model/Paper)을 확정. 불명이면 `unknown` + 중단 후 근거 탐색.
- 모든 수량·단가에 단위. 수량 단위 ↔ 단가 단위 불일치(mm vs m, m² vs 평)는 검증 실패 사유.

## 규칙 4. 순수량과 할증 분리

- 물량산출(takeoff)은 설계 순수량만. 할증률은 단가 단계에서 출처와 함께 한 번만 적용한다(이중 할증 금지).

## 규칙 5. 도면은 기밀

- 고객·실제 도면은 `data/drawings/private/`에만 두고 git에 올리지 않는다.
- 온라인 변환기·외부 API·공개 저장소에 업로드하지 않는다. 변환은 로컬 도구로만.
- 이 규칙의 예외는 CEO도 승인할 수 없다(사용자 전용).

## 규칙 6. 생성과 검증 분리

- 결과를 만든 에이전트가 최종 승인하지 않는다. `estimate-verifier`가 원 데이터에서 표본 재계산으로 검증(7점 미만 반려).

## 규칙 7. 결정은 CEO 에이전트 먼저

- 권한 밖 결정은 사용자에게 바로 묻지 않고 `bim-ceo`에 질의. CEO가 `ESCALATE_TO_USER`로 판정한 것만 사용자에게(질문 + 선택지 + CEO 추천안을 한 번에). (사용자 지시 2026-11-09)

## 규칙 8. 연도별 수치는 기억으로 쓰지 않는다

- 노임단가, 제경비·보험료 요율, 표준품셈 개정 내용은 매년/반기 바뀐다. 모델의 기억에 있는 숫자를 쓰지 않고, 이번에 출처에서 확인한 값만 `data/prices/`에 기준일과 함께 넣는다.

## 규칙 9. 무한 반복 방지 (watchdog)

- 같은 방식으로 3번 실패하면 멈추고 보고한다.
- 자율 루프는 사이클 상한(기본 5)과 no-progress 중단 조건을 둔다.
- 서브에이전트 호출은 실제로 역할 경계를 넘을 때만.

## 규칙 10. 하지 않은 검증을 했다고 말하지 않는다

- 테스트를 못 돌렸으면 못 돌렸다고, 표본만 확인했으면 표본 범위를 밝힌다.
