# Operating Rules

> 견적 숫자는 실제 돈에 쓰인다. node_trade의 "실거래 안전 규칙"에 해당하는 문서.
> 규칙 번호는 고정한다 — 새 규칙은 뒤에 추가하고, 폐기 시 번호를 지우지 말고 "폐기(날짜, 사유)"로 표시한다.
> 사고에서 나온 규칙은 `incident-log.md`의 해당 항목을 근거로 링크한다.

## 규칙 1. 추적성 — 근거 없는 숫자는 없다

- 수량 행: 근거 도면 파일 + 레이어 + 엔티티 handle 목록 + 산출식.
- 단가 행: 출처 기관·자료명 + 기준일 + URL/문서 위치 + 부가세 포함 여부.
- 근거를 못 붙이면 숫자를 넣지 않는다.

## 규칙 2. 모르면 표시한다 — 상태 어휘

> 승인 어휘 전체 목록(D-008 Q12, D-014 Q16). 정의의 원본은 `docs/feature_definition.md` v0.2 0절이다. 상태는 대상마다 정확히 하나를 붙인다(귀속 등식, F-009). `STALE`만 상태가 아니라 PRICED 성분에 덧붙는 플래그다.

**도면 인스턴스(INSERT) 상태**

| 표시 | 의미 | 합계 처리 |
|---|---|---|
| `MAPPED` | 품목에 매핑돼 수량에 포함됨 | 수량에 포함 |
| `EXCLUDED:<사유>` | 정해진 사유로 수량에서 뺌. 사유 코드: `PAPER_SPACE`, `LAYER_FROZEN`, `LAYER_OFF`, `EXCLUDED_LAYER`, `LEGEND_AREA`, `ZERO_SCALE`, `DUPLICATE`, `RULE_IGNORE` | 수량 제외, 제외 목록에 사유와 handle 표시 |
| `UNMAPPED` | 매칭되는 규칙이 없음 | 수량표 하단 별도 목록 |
| `CONFLICT` | 같은 우선순위의 규칙이 2개 이상 매칭됨 | 수량에 넣지 않음, 별도 목록 |

**파일 상태**

| 표시 | 의미 | 합계 처리 |
|---|---|---|
| `UNIT_UNKNOWN` | 단위가 확정되지 않아 수량을 내지 않음. 사용자가 단위를 지정하면 해제(D-010) | 수량 칸에 0이 아니라 "단위 확인 필요" 표시, 세트 합계 비움 |
| `INCOMPLETE` | XREF 등으로 도면 내용 일부가 빠졌을 수 있음 | 수량은 내되 표시 |

**단가 성분·내역서 행 상태**

| 표시 | 의미 | 합계 처리 |
|---|---|---|
| `PRICED` | 출처로 되돌아갈 수 있는 단가가 있음 | 합계에 포함 |
| `UNPRICED` | 단가 출처 못 찾음 | 합계에서 제외, "미확인 N품목" 명시 |
| `NA` | 근거 있는 해당 없음(출처 자료가 그 성분을 0 또는 해당 없음으로 명시) | 근거와 함께 표시 |
| `PARTIAL` | (내역서 행) 성분 중 일부만 PRICED | 행 합계는 PRICED 성분만, 표시 |
| `ESTIMATED` | 요청에 의해 추정한 단가. MVP에서는 생성하지 않음 | 별도 소계, Gate 3에서 CEO 판정 |
| `STALE` | (플래그) 단가 기준일 1년 초과(노임은 해당 반기 아님) | 포함하되 경고 |

**경고 코드** (수량을 바꾸지 않고 경고 시트에 코드·파일·handle·개수·설명으로 남는다. 의미는 feature_definition 0절 기준)

| 코드 | 의미 | 근거 |
|---|---|---|
| `NESTED_MATCH_HIDDEN` | 매칭돼 탐색을 멈춘 블록 안에 다른 매핑 규칙에 매칭될 자식 INSERT가 있음. IGNORE에만 매칭되는 자식도 포함, 품목 매칭/IGNORE 매칭 개수를 나눠 적음 | D-009 Q10, D-014 Q15 |
| `UNIT_USER_SET` | 헤더가 없거나 0인 파일에 사용자가 단위를 지정함 | D-014 Q13 |
| `UNIT_OVERRIDE` | 헤더에 값이 있는데 사용자가 다른 단위를 지정함(빈칸 채움보다 위험이 커서 구분) | D-010, D-014 Q13 |
| `DUPLICATE` | (제외 사유 코드이기도 함) 같은 위치 중복 삽입, 짝 handle 기록 | D-009 Q2 |

> F-002의 `UNIT_USER_SET`/`UNIT_OVERRIDE` 구분은 D-014 Q13 기준으로 feature_definition에 반영됨(2026-11-09).

그 밖의 경고 코드(`XREF`, `DYNAMIC_UNRESOLVED`, `ACIS`, `UNDERLAY`, `PROXY`, `UNKNOWN_ENTITY`, `BLOCK_UNIT_DIFF`, `SET_UNIT_DIFF`, `LEGEND_SUSPECT`, `NON_BLOCK_SYMBOL`, `UNIT_MISMATCH`)는 feature_definition 0절 표를 본다. CEO가 어휘로 명시 승인한 것은 `NESTED_MATCH_HIDDEN`이며 나머지의 wiki 승격은 필요할 때 한다.

조용히 버리거나 0으로 채우는 것은 금지.

## 규칙 3. 단위 먼저

- 파싱 첫 단계에서 도면 단위(`$INSUNITS`)·축척·공간(Model/Paper)을 확정. 불명이면 `unknown` + 중단 후 근거 탐색.
- 모든 수량·단가에 단위. 수량 단위 ↔ 단가 단위 불일치(mm vs m, m² vs 평)는 검증 실패 사유.

## 규칙 4. 순수량과 할증 분리

- 물량산출(takeoff)은 설계 순수량만. 할증률은 단가 단계에서 출처와 함께 한 번만 적용한다(이중 할증 금지).

## 규칙 5. 도면은 기밀

- 고객·실제 도면은 `data/drawings/private/`에만 두고 git에 올리지 않는다.
- 온라인 변환기·외부 API·공개 저장소에 업로드하지 않는다. 변환은 로컬 도구로만.
- 이 규칙의 예외는 CEO도 승인할 수 없다(사용자 전용).

## 규칙 6. 생성과 검증 분리

- 결과를 만든 에이전트가 최종 승인하지 않는다. `estimate-verifier`가 원 데이터에서 표본 재계산으로 검증(7점 미만 반려).

## 규칙 7. 결정은 CEO 에이전트 먼저

- 권한 밖 결정은 사용자에게 바로 묻지 않고 `bim-ceo`에 질의. CEO가 `ESCALATE_TO_USER`로 판정한 것만 사용자에게(질문 + 선택지 + CEO 추천안을 한 번에). (사용자 지시 2026-11-09)

## 규칙 8. 연도별 수치는 기억으로 쓰지 않는다

- 노임단가, 제경비·보험료 요율, 표준품셈 개정 내용은 매년/반기 바뀐다. 모델의 기억에 있는 숫자를 쓰지 않고, 이번에 출처에서 확인한 값만 `data/prices/`에 기준일과 함께 넣는다.

## 규칙 9. 무한 반복 방지 (watchdog)

- 같은 방식으로 3번 실패하면 멈추고 보고한다.
- 자율 루프는 사이클 상한(기본 5)과 no-progress 중단 조건을 둔다.
- 서브에이전트 호출은 실제로 역할 경계를 넘을 때만.

## 규칙 10. 하지 않은 검증을 했다고 말하지 않는다

- 테스트를 못 돌렸으면 못 돌렸다고, 표본만 확인했으면 표본 범위를 밝힌다.

## 규칙 11. 제비율에는 기본값이 없다 (D-006)

- 간접노무비율, 기타경비율, 산재·고용보험료율, 산업안전보건관리비, 일반관리비율, 이윤율은 코드에 숫자를 넣지 않는다.
- 사용자 입력 파라미터 파일로 받고, 값마다 근거(고시·예규명, 판·개정일, 적용 기준일, 사내 기준 여부)를 함께 받는다.
- 값이 비어 있으면 해당 원가 항목을 계산하지 않고 "제비율 미입력"으로 표시한다. MVP는 원가계산서를 만들지 않는다(D-007).

## 규칙 12. 사용자 입력 인공은 인공 근거 7항목이 있어야 한다 (D-015)

- 노무비는 기본 `UNPRICED`다. "사용자 입력 인공 × 노임" 구조는 사용자가 자기 권한으로 열람한 품셈에서 직접 입력한 인공에 한해 허용한다.
- 입력할 때 품셈명, 발행처, 판·적용기간, 항목 번호·명칭, 직종, 인공 값, 입력자를 모두 받는다. 하나라도 없으면 받지 않는다.
- 이 데이터는 사용자 비공개 경로에 두고 git에서 제외하며, 출처 유형은 사용자 입력으로 기록한다.
- 품셈의 직종명이 노임 스냅샷의 직종과 정확히 일치할 때만 노무비를 계산한다. 불일치하면 `UNPRICED`(사유 "직종 노임 출처 없음").
- 전기 직종 노임의 공표 주체는 미확인이다(D-015, NEED_RESEARCH).

## 규칙 13. 품셈 수치는 저장소에 번들하지 않는다 (D-015)

- 에이전트는 표준품셈 수치를 저장소에 옮겨 적거나 번들하지 않는다. 제3자 사본(pstatic, kseis 등)도 쓰지 않는다.
- 전기공사 표준품셈의 이용조건 본문은 확인되지 않았다. 규칙 8(기억 수치 금지)과 함께 적용한다.

## 규칙 14. 원 미만(끝수) 처리에는 기본값이 없다 (D-015)

- 끝수 처리는 설정값이며 기본값을 두지 않는다. 설정되기 전에는 계산값을 그대로 보존하고 "끝수 처리 미정"으로 표시한다.
- 공식 조문은 아직 찾지 못했다(후속 조사 대상). 구현 시점은 M2이며 Gate 2 ADR 승인 후다(D-014 Q14).
