## 0. 공통 규칙

모든 F-ID에 적용한다. 각 F-ID의 검증 조건과 별도로 회귀 테스트에서 상시 확인한다.

| ID | 규칙 | 검증 조건 |
|---|---|---|
| C-1 | **로컬 처리.** 파싱, 집계, 단가 적용, 출력 중 외부 네트워크 호출을 하지 않는다. 단가 스냅샷은 미리 받아 둔 로컬 파일만 읽는다 | 네트워크를 차단한 환경에서 전체 테스트가 통과한다 |
| C-2 | **조용한 누락·0 채움 금지.** 모든 INSERT 인스턴스와 모든 단가 성분은 정해진 상태 중 정확히 하나로 귀속된다 | 귀속 등식 위반 0(F-009). 출처 없는 0 금액 셀 0(F-017) |
| C-3 | **단위 명시.** 모든 수량과 단가에 단위가 있다 | 산출물의 수량·단가 행 중 단위 칸이 빈 행 0 |
| C-4 | **결정성.** 입력 파일, 규칙 파일, 품목 사전, 단가 스냅샷이 같으면 산출 내용이 같다(실행 시각 제외) | 2회 실행 비교에서 차이 0(S-6) |
| C-5 | **데이터와 코드 분리.** 매핑, 품목, 단가, 요율, 허용오차 기본값은 데이터 파일에 둔다 | 코드 안에 단가·요율 숫자 리터럴 0(리뷰 체크리스트). 매핑을 바꿀 때 코드 변경이 필요 없다 |

| C-8 | **실행 기록.** 모든 실행은 입력 해시, 규칙·사전·스냅샷 해시, 도구 버전, 실행 시각을 남긴다 | 산출물 실행정보 필드 누락 0 |

### 상태 표시 어휘 (D-008 Q12 승인)

`LLM_wiki/operating-rules.md` 규칙 2의 기존 어휘(`UNMAPPED`, `UNPRICED`, `ESTIMATED`, `STALE`)에 아래 추가 어휘를 더한 것이 승인된 전체 목록이다. wiki(`operating-rules.md` 규칙 2, `domain-terms.md`) 반영은 `bim-docs` 몫이며, 이 문서는 정의만 둔다. 상태는 대상마다 정확히 하나를 붙인다(C-2). 단, `STALE`은 상태가 아니라 PRICED 성분에 덧붙는 플래그다.

| 표시 | 구분 | 대상 | 의미 | 출처 |
|---|---|---|---|---|
| `MAPPED` | 추가(승인) | INSERT 인스턴스 | 품목에 매핑돼 수량에 포함됨 | D-008 |
| `EXCLUDED:<사유>` | 추가(승인) | INSERT 인스턴스 | 정해진 사유로 수량에서 뺌. 사유 코드: `PAPER_SPACE`, `LAYER_FROZEN`, `LAYER_OFF`, `EXCLUDED_LAYER`, `LEGEND_AREA`, `ZERO_SCALE`, `DUPLICATE`, `RULE_IGNORE`(우선순위는 F-006) | D-008, D-009 |
| `UNMAPPED` | 기존 | INSERT 인스턴스 | 매칭되는 규칙이 없음 | 규칙 2 |
| `CONFLICT` | 추가(승인) | INSERT 인스턴스 | 같은 우선순위의 규칙이 2개 이상 매칭됨. 수량에 넣지 않음 | D-008 |
| `UNIT_UNKNOWN` | 추가(승인) | 파일 | 단위가 확정되지 않아 수량을 내지 않음. 사용자가 단위를 지정하면 해제된다(D-010) | D-008, D-010 |
| `INCOMPLETE` | 추가(승인) | 파일 | XREF 등으로 도면 내용 일부가 빠졌을 수 있음. 수량은 내되 표시함 | D-008 |
| `PRICED` | 보조(D-008 승인 목록에 명시 없음, `UNPRICED`의 반대값) | 단가 성분(재료·노무·경비) | 출처로 되돌아갈 수 있는 단가가 있음 | v0.1부터 사용. 기획 9.2 Q16 |
| `UNPRICED` | 기존 | 단가 성분 | 출처 있는 단가가 없음. 0으로 채우지 않음 | 규칙 2 |
| `NA` | 추가(승인) | 단가 성분 | 근거가 있는 해당 없음(출처 자료가 그 성분을 0 또는 해당 없음으로 명시한 경우) | D-008 |
| `PARTIAL` | 추가(승인) | 내역서 행 | 성분 중 일부만 PRICED | D-008 |
| `ESTIMATED` | 기존 | 단가 성분 | 추정 단가. **MVP에서는 생성하지 않는다**(F-017) | 규칙 2 |
| `STALE` | 기존(플래그) | PRICED 성분 | 기준일 1년 초과, 노임은 해당 반기 아님 | 규칙 2 |

## 1. 입력·파싱

### F-001 DXF 로드

**한 줄 설명**: 도면 세트(DXF 1개 이상)를 읽고, 파일마다 식별 정보와 읽기 상태를 확정한다.

**입력**
| 항목 | 형식 | 필수 |
|---|---|---|
| DXF 파일 경로 | 1개 이상 | 필수 |
| 세트 이름 | 텍스트 | 선택(없으면 첫 파일명) |
| 파일별 구분 라벨(층·계통) | 텍스트 | 선택(없으면 파일명) |

**처리**
1. 확장자와 파일 서명으로 DXF인지 확인한다. DWG가 들어오면 읽지 않고 "CAD에서 DXF로 저장해 주세요(D-002)"라는 안내와 함께 거부한다.
2. 파일마다 SHA-256 해시, 크기, DXF 버전(`$ACADVER`)을 기록한다.
3. 파서로 연다. 구조 오류가 있으면 해당 파일을 `읽기 실패`로 기록하고, 원인 메시지를 남긴다.
4. 세트 안에 해시가 같은 파일이 2개 이상 있으면 실행을 중단한다(같은 도면 이중 합산 방지).

**출력**: 파일별 source 정보(파일명, 해시, 버전, 크기, 읽기 상태, 라벨). 정규화 레코드(F-004)의 `source`가 된다.

**동작 규칙**
- 읽기에 실패한 파일이 하나라도 있으면 세트 합계를 내지 않는다. 정상 파일의 파일별 결과는 낸다. 실패한 파일의 수량은 0이 아니라 "읽기 실패"로 표시한다.
- 입력 파일을 수정하지 않는다(읽기 전용).

**검증 조건**
- [ ] T-20(손상 DXF): 해당 파일이 `읽기 실패`로 표시되고, 수량 행 0, 세트 합계 행 0이다.
- [ ] DWG 파일을 입력하면 거부 메시지가 나오고 처리된 엔티티가 0이다.
- [ ] 기록된 해시가 독립 도구로 계산한 SHA-256과 일치한다(합성 파일 전부).
- [ ] 같은 파일을 두 번 지정하면 실행이 중단되고 산출물이 생성되지 않는다.
- [ ] 실행 전후 입력 파일 해시가 같다.

**파이프라인 단계**: 1 파싱 | **관련 결정**: D-002, D-004 | **저니**: 1

### F-002 도면 단위 판정

**한 줄 설명**: 파일마다 도면 단위를 확정한다. 확정하지 못하면 그 파일의 수량을 내지 않는다.

**입력**: F-001에서 로드한 문서, (선택) 파일별 사용자 지정 단위

**처리**
1. `$INSUNITS`를 읽어 단위(mm, m 등)로 변환하고, 판정 출처를 `header`로 기록한다.
2. 값이 없거나 0이면 `UNIT_UNKNOWN`으로 둔다.
3. **사용자 지정 단위(D-010)**: 사용자가 파일 단위를 지정하면 그 값을 쓰고 판정 출처를 `user`로 기록한다. `UNIT_UNKNOWN` 파일도 사용자 지정이 있으면 수량을 낸다.
   - 지정 사실(파일, 헤더 원값, 지정값, 출처 `user`)을 **실행정보 시트와 경고 시트 양쪽**에 남긴다.
   - 헤더 값이 있는데 지정값이 다르면 `UNIT_OVERRIDE`, 헤더가 없거나 0인데 지정하면 `UNIT_USER_SET` 경고를 낸다(D-014 Q13).
   - 지정값이 헤더 값과 같으면 경고 코드 없이 경고 시트에 "사용자 지정 = 헤더" 기록 행만 남긴다.
4. 블록 정의마다 단위가 지정돼 있고 모델 단위와 다르면 `BLOCK_UNIT_DIFF` 경고를 낸다(개수에는 영향 없음, 기록용).
5. 세트 안에서 파일 간 단위가 다르면 `SET_UNIT_DIFF` 경고를 내고 파일별 단위로 처리한다.

**출력**: 파일별 `units`(값, 판정 출처 header/user/unknown, 경고)

**동작 규칙**
- `UNIT_UNKNOWN` 파일(사용자 지정 없음)은 정규화 레코드까지만 만든다. 물량 단계에서 그 파일의 수량 행을 만들지 않고 "단위 확인 필요"로 표시한다(D-002 d). 단위에 따라 달라지는 값(중복 허용오차, 범례 영역)을 판정할 수 없기 때문이다.
- 단위를 추정해서 채우지 않는다. 좌표 범위로 추정한 값은 경고 문구에 "추정 후보"로만 보여 주며(선택 기능), **수량 산출에는 쓰지 않는다**(D-010). 추정 후보를 사용자 지정으로 자동 승격하지 않는다.
- 축척(1/100 등)은 EA 집계에 쓰지 않으므로 MVP에서 판정하지 않는다.

**검증 조건**
- [ ] T-07(`$INSUNITS` 누락·0): `UNIT_UNKNOWN`으로 표시되고 수량 행 0이다. 사용자가 단위를 지정해 다시 실행하면 정답 수량과 일치하고, 판정 출처 `user`가 실행정보 시트와 경고 시트에 각 1행 이상 기록되며, `UNIT_USER_SET` 경고가 해당 파일당 1건 나오고 `UNIT_OVERRIDE`는 0건이다(D-014 Q13).
- [ ] 헤더가 mm인 파일에 m를 지정하면 `UNIT_OVERRIDE` 경고 1건에 헤더값(mm)과 지정값(m)이 모두 기록된다. 헤더와 같은 값(mm)을 지정하면 `UNIT_OVERRIDE`는 0건이고 경고 시트에 기록 행만 1건 있다.
- [ ] 좌표 추정 후보 기능을 켠 상태에서 사용자 지정이 없으면 `UNIT_UNKNOWN` 파일의 수량 행이 여전히 0이다(추정값 사용 0건).
- [ ] T-06(mm 파일과 m 파일 세트, 블록 단위 상이): `SET_UNIT_DIFF`, `BLOCK_UNIT_DIFF` 경고가 각 1건 이상 나오고, 개수는 정답과 일치한다.
- [ ] 합성 세트의 모든 파일에 단위와 판정 출처가 기록된다(누락 0).

**파이프라인 단계**: 1 파싱 | **관련 결정**: D-002(d), D-010, operating-rules 규칙 3 | **저니**: 2

### F-003 지원 범위 밖 요소 경고

**한 줄 설명**: 파서가 해석하지 못하거나 수량이 빠질 수 있는 요소를 조용히 무시하지 않고 경고 목록으로 낸다.

**입력**: 로드한 문서

**처리**: 다음 요소를 찾아 경고 코드, 파일, 레이어, handle, 개수, 영향 설명을 기록한다.

| 경고 코드 | 대상 | 파일 상태 영향 |
|---|---|---|
| `XREF` | 외부 참조 블록 정의와 그 INSERT | 파일을 `INCOMPLETE`로 표시 |
| `DYNAMIC_UNRESOLVED` | 원본 이름을 판별하지 못한 `*U` 익명 블록 INSERT | 없음(F-005, F-009에서 처리) |
| `ACIS` | 3DSOLID, REGION, BODY 등 | 없음(MVP 집계 대상 아님, 개수만 보고) |
| `UNDERLAY` | PDF/DWF/DGN 언더레이, IMAGE | 파일을 `INCOMPLETE`로 표시(언더레이 속 기호는 셀 수 없음) |
| `PROXY` | PROXY_ENTITY | 파일을 `INCOMPLETE`로 표시 |
| `UNKNOWN_ENTITY` | 그 밖에 파서가 해석하지 못한 엔티티 유형 | 개수만 보고 |

**출력**: 경고 목록. 정규화 레코드의 `unsupported`가 되고, 수량산출서 경고 시트(F-010)에 들어간다.

**동작 규칙**
- `INCOMPLETE` 파일도 수량은 낸다. 단, 요약 시트의 해당 파일 열과 세트 합계에 `INCOMPLETE` 표시를 붙인다.
- 경고는 개수로만 뭉뚱그리지 않는다. 담당자가 CAD에서 찾을 수 있게 handle을 함께 낸다.
- ACIS·PROXY·UNDERLAY·XREF를 합성 DXF로 만들 수 있는지는 스파이크 확인 항목 (d)(D-012)다. 만들 수 없는 요소는 F-012의 "합성 불가"로 표시한다.

**검증 조건**
- [ ] T-13(XREF), T-17(ACIS·PROXY·UNDERLAY): 심어 둔 요소마다 해당 코드 경고가 1건 이상 있고, 경고의 handle이 정답 handle과 일치한다(재현율 100%).
- [ ] T-13 파일이 `INCOMPLETE`로 표시되고, 세트 합계에도 표시가 따라간다.
- [ ] 함정 요소가 없는 기본 파일(T-01)에서 경고가 0건이다(오경보 0).

**파이프라인 단계**: 1 파싱 | **관련 결정**: D-002(c) | **저니**: 2

### F-004 정규화 레코드 출력

**한 줄 설명**: 도면을 포맷 중립 레코드로 바꾼다. 모든 레코드는 원본 파일, 레이어, 블록, handle, 단위로 되돌아갈 수 있다.

**입력**: F-001~F-003 결과

**처리**
1. 모든 INSERT를 인스턴스 단위로 전개한다(중첩·MINSERT 전개 규칙은 F-005). 인스턴스마다 레코드 1개를 만든다.
2. 필수 필드는 다음과 같다.
   - 원본 파일(이름, 해시), 공간(Model/Paper)
   - 레이어(자체), 유효 레이어(F-005 상속 규칙 적용)
   - 블록 정의 이름, 원본 블록 이름(동적 블록 판별 결과, 없으면 null과 사유)
   - **원본 객체 ID**: INSERT handle. 중첩이면 부모 INSERT handle 경로와 블록 정의 안 handle
   - 삽입점(WCS, 파일 단위), 회전, 스케일(x, y, z), MINSERT 행·열 인덱스
   - ATTRIB 키-값, 레이어 상태(동결/끔/잠금), 파일 단위
3. TEXT/MTEXT는 내용과 위치를 레코드로 남긴다(범례 의심 판정에 쓴다, F-006).
4. INSERT가 아닌 엔티티는 유형·레이어별 개수 요약을 남긴다. 매핑 규칙이 참조하는 레이어에 있는 것은 개별 handle도 남긴다(F-009 비블록 기호 경고용).

**출력**: 정규화 레코드(`LLM_wiki/estimation-pipeline.md`의 drawing.json에 해당). 스키마와 직렬화 형식은 ADR에서 정한다.

**동작 규칙**
- 필드 이름은 DXF 고유 용어에 묶이지 않게 짓는다. 나중에 IFC 어댑터가 같은 레코드를 채울 수 있어야 한다(D-002 a). 예: handle → 원본 객체 ID.
- 같은 블록 정의 안의 엔티티는 인스턴스마다 같은 handle을 가진다. 그래서 중첩 인스턴스의 식별 키는 반드시 "부모 경로 + 내부 handle"로 한다.
- handle 경로로 원본 엔티티를 역추적할 수 있는지는 `cad-parser` 스파이크 확인 항목 (f)(D-012)이다. 결과에 따라 ADR에서 식별 키 표현을 확정한다.

**검증 조건**
- [ ] 합성 세트에서 전개 후 INSERT 인스턴스 수가 정답과 같고, 인스턴스마다 레코드가 정확히 1개다(중복 0, 누락 0).
- [ ] 필수 필드의 null 비율이 0이다(원본 블록 이름은 null이면 사유가 있어야 한다).
- [ ] 레코드의 원본 객체 ID로 원본 DXF에서 해당 엔티티를 찾을 수 있다. 합성 세트 전수에서 100%, 중첩 인스턴스 포함.
- [ ] 식별 키가 세트 안에서 유일하다(중복 0).

**파이프라인 단계**: 1 파싱 (출력 = 단계 1→2 계약) | **관련 결정**: D-002(a) | **저니**: 3

### F-011 변환 이력 기록 · 변환 어댑터 인터페이스

**한 줄 설명**: DXF가 어떤 경로로 만들어졌는지 기록하고, DWG→DXF 변환기를 교체할 수 있는 자리를 정의한다. MVP 구현은 "사용자 수동 저장" 하나다.

**입력**
| 항목 | 필수 |
|---|---|
| DXF 파일 | 필수 |
| 변환 수단 선언: `MANUAL_SAVE`(사용자가 CAD에서 저장, CAD 이름·버전은 선택 입력), `ORIGINAL_DXF`(받을 때부터 DXF), `UNKNOWN` | 필수(기본값 `UNKNOWN`) |
| 원본 DWG 파일 또는 그 해시 | 선택 |

**처리**
1. 이력 레코드를 만든다: 변환 수단, 변환기 이름·버전(선언값 또는 "미상"), 원본 해시(없으면 "원본 미제공"), DXF 해시, DXF 헤더 버전, 기록 시각.
2. 원본 DWG 파일이 주어지면 해시만 계산하고 내용은 읽지 않는다.
3. 어댑터 인터페이스 계약: "원본 경로 → DXF 경로 + 이력 레코드". 실패하면 이력에 실패를 기록하고 DXF를 내지 않는다.

**출력**: 파일별 변환 이력. 수량산출서와 내역서의 실행정보 시트에 들어간다.

**동작 규칙**
- MVP에서 실행 가능한 어댑터는 `MANUAL_SAVE`, `ORIGINAL_DXF`(기록만 하는 no-op)뿐이다. AutoCAD·BricsCAD·ODA 어댑터는 사용자 확인 전까지 구현하거나 실행하지 않는다(D-002 2·3순위).
- 변환 전후 엔티티 수 비교는 원본 DWG를 읽을 수 없으므로 MVP에서 하지 않는다. 그 사실을 이력에 "비교 불가"로 남긴다.
- 빈칸으로 두지 않는다. 모르는 값은 "미상" 또는 "원본 미제공"으로 쓴다.

**검증 조건**
- [ ] 모든 실행 산출물의 실행정보에 입력 파일마다 이력 레코드가 1건씩 있다(100%).
- [ ] 원본 DWG를 주면 기록된 해시가 독립 계산값과 일치한다. 주지 않으면 "원본 미제공"으로 기록된다.
- [ ] 등록된 어댑터 중 외부 프로그램을 실행하는 어댑터가 0개다(D-002 준수, 코드 리뷰 체크).

**파이프라인 단계**: 0 입력 전처리 | **관련 결정**: D-002(b) | **저니**: 0, 1

## 2. 물량

### F-005 블록 집계

**한 줄 설명**: 모델스페이스의 블록 삽입을 중첩, MINSERT, 동적 블록, 스케일·미러까지 반영해 인스턴스 단위로 센다.

**입력**: 정규화 레코드(F-004), 매핑 규칙(F-007, 중첩 탐색을 멈추는 지점을 정하기 위해)

**처리**
1. **전개**: 모델스페이스 INSERT부터 재귀적으로 들어간다. MINSERT는 행 × 열 개수만큼 인스턴스를 만든다.
2. **중첩 탐색 정지(D-009 Q10)**: 인스턴스가 매핑 규칙(IGNORE 포함)에 매칭되면 그 블록 안으로는 내려가지 않는다. 매칭되지 않으면 안으로 내려가 자식 INSERT를 평가한다. 규칙에 `descend` 옵션이 있으면 부모와 자식을 모두 센다(예: 분전반과 내부 차단기를 둘 다 품목으로 셀 때).
2-1. **숨은 매칭 경고 `NESTED_MATCH_HIDDEN`(D-009 Q10 조건)**: 탐색을 멈춘 인스턴스마다, 그 블록 정의 안(모든 깊이)의 자식 INSERT를 매핑 규칙에 **평가만** 한다(수량·귀속에는 넣지 않음). 다른 매핑 규칙에 매칭되는 자식이 1개 이상이면 경고 1건을 낸다.
   - 경고 필드: 파일, 부모 인스턴스 식별 키(handle 경로), 부모 블록 이름, 부모가 매칭된 규칙 ID와 결과(품목 ID 또는 IGNORE), 숨은 자식 개수(품목 매칭 / IGNORE 매칭으로 구분), 자식이 매칭된 규칙 ID 목록.
   - IGNORE에만 매칭되는 자식도 경고 대상에 넣는다(보수적 해석, 기획 9.2 Q15).
   - `descend`가 켜진 부모는 자식이 실제로 집계되므로 경고하지 않는다.
   - 이 경고는 숨은 자식을 수량에 넣지 않는다. 넣으려면 담당자가 해당 규칙에 `descend`를 켜거나 부모 규칙을 고친다(F-007).
3. **유효 레이어**: 블록 안 엔티티의 레이어가 `0`이면 부모 INSERT의 레이어를 상속한다(재귀).
4. **스케일·회전·미러**: 개수에 영향을 주지 않는다. 음수 스케일(미러)도 1개로 센다. 값은 레코드에 기록한다. 스케일 성분 중 0이 있으면 `EXCLUDED:ZERO_SCALE`로 처리한다(F-006).
5. **동적 블록(`*U`)**: 원본 블록 이름을 판별할 수 있으면 그 이름을 매핑 키로 쓰고, 판별 근거를 기록한다. 판별할 수 없으면 `*U` 이름을 매핑 키로 쓰고 `DYNAMIC_UNRESOLVED` 경고를 낸다. 사용자 규칙이 그 `*U` 이름을 직접 매핑하면 집계한다.
6. **수량 근거**: 블록 정의 수가 아니라 INSERT 인스턴스 수만 센다. 삽입되지 않은 블록 정의는 0이다.

**출력**: (파일, 매핑 키, 유효 레이어, ATTRIB)별 인스턴스 목록. F-006, F-007, F-009의 입력이 된다. `NESTED_MATCH_HIDDEN` 경고 목록(수량산출서 경고 시트로 간다).

**동작 규칙**
- `*U` 이름은 저장할 때마다 바뀔 수 있다. 따라서 `*U` 이름을 직접 쓰는 규칙은 해당 파일 범위로 한정하라는 경고를 F-014 초안에 넣는다.
- 동적 블록 원본 이름을 판별할 수 있는지는 확인되지 않았다(조사 문서). `cad-parser` 스파이크 확인 항목 (a), MINSERT 전개는 항목 (c)이며 결과를 ADR에 기록한다(D-012).
- 귀속 등식(F-009)의 "전개 후 인스턴스"에는 탐색을 멈춘 블록 안의 자식이 들어가지 않는다. 숨은 자식은 `NESTED_MATCH_HIDDEN` 경고로만 드러나며, 그래서 이 경고를 조용히 생략하면 안 된다.

**검증 조건** (모두 합성 정답과 비교해 수량이 정확히 일치해야 한다)
- [ ] T-01 기본 4종 기구 개수 일치.
- [ ] T-02 2단·3단 중첩: 자식 수량 = 부모 인스턴스 수 × 정의 내 자식 수.
- [ ] T-03 부모와 자식이 모두 매핑 대상: 기본 설정에서 부모만 집계되고 자식 0. `descend` 설정에서 둘 다 집계.
- [ ] T-03 숨은 매칭(D-009): (a) 품목 매핑 부모 안의 매핑 대상 자식, (b) IGNORE된 래퍼 블록 안의 기구 블록 — 두 케이스 모두 `NESTED_MATCH_HIDDEN` 경고 수 = 부모 인스턴스 수, 경고마다 부모 handle 경로와 숨은 자식 개수가 정답과 일치한다(재현율 100%). 래퍼 안 기구의 수량은 0이다.
- [ ] T-03 오경보: (c) `descend`가 켜진 부모, (d) 자식이 어떤 규칙에도 매칭되지 않는 부모에서 `NESTED_MATCH_HIDDEN`이 0건이다.
- [ ] T-04 동적 블록: (a) 판별 가능한 케이스는 원본 이름으로 매핑돼 개수가 일치한다(합성으로 재현할 수 없으면 실도면 단계로 넘기고 그 사실을 테스트 목록에 기록). (b) 판별 불가 케이스는 `DYNAMIC_UNRESOLVED` 경고와 함께 UNMAPPED에 정답 개수만큼 나온다.
- [ ] T-08 스케일 2배, 비균일, 음수(미러), 회전: 개수 일치. T-08 안의 스케일 0 인스턴스는 `ZERO_SCALE` 제외.
- [ ] T-14 MINSERT 3×4: 12개.
- [ ] T-15 레이어 `0` 상속: 유효 레이어가 정답과 일치하고, 레이어 조건 매핑 결과도 일치한다.
- [ ] T-21 삽입되지 않은 블록 정의: 수량 0, UNMAPPED 0.

**파이프라인 단계**: 2 물량산출 | **관련 결정**: D-003, D-004(a), D-009(Q10), D-012 | **저니**: 3

### F-006 집계 제외 규칙

**한 줄 설명**: 세면 안 되는 인스턴스(페이퍼스페이스, 숨긴 레이어, 범례, 중복 삽입 등)를 사유와 함께 빼고, 뺀 목록을 그대로 보여 준다.

**입력**: F-005 인스턴스, 매핑 규칙 파일의 제외 설정(제외 레이어, 파일별 범례 영역, 중복 허용오차, 숨김 레이어 포함 여부)

**처리**: 사유는 아래 우선순위로 하나만 붙인다.

| 순위 | 사유 | 판정 |
|---|---|---|
| 1 | `PAPER_SPACE` | 페이퍼스페이스(레이아웃)에 있는 인스턴스. 항상 제외한다 |
| 2 | `LAYER_FROZEN` | 자신이나 상위 INSERT 경로 중 하나라도 동결 레이어에 있음 |
| 3 | `LAYER_OFF` | 유효 레이어가 꺼져 있음 |
| 4 | `EXCLUDED_LAYER` | 규칙 파일이 지정한 제외 레이어 |
| 5 | `LEGEND_AREA` | 규칙 파일에 파일별로 지정한 범례 영역(직사각형, 모델 좌표) 안의 삽입점 |
| 6 | `ZERO_SCALE` | 스케일 성분 중 0이 있음 |
| 7 | `DUPLICATE` | 같은 파일·공간에서 매핑 키가 같고 삽입점 거리가 허용오차 이하. handle 순서상 첫 인스턴스만 세고 나머지를 제외하며, 쌍을 기록한다 |
| 8 | `RULE_IGNORE` | 매핑 규칙의 IGNORE(사유 텍스트 필수, F-007) |

**범례 의심 경고(제외하지 않음)**: 텍스트가 범례 키워드(기본 "범례", "LEGEND", "기호"이며 규칙 파일에서 바꿀 수 있음)와 일치하고, 그 주변에 매핑 대상 블록이 서로 다른 종류로 여러 개 모여 있으면 `LEGEND_SUSPECT` 경고를 낸다. 경고에는 영역 후보 좌표와 해당 handle을 붙인다. "주변"과 "여러 개"의 기본값은 데이터 파일에 둔다(값은 구현 시 정하고 ADR에 기록).

**출력**: 제외 목록(사유, 파일, 레이어, 블록, handle, DUPLICATE이면 짝 handle), `LEGEND_SUSPECT` 경고, 숨김 레이어 제외 건수(파일별·세트 합계, `LAYER_FROZEN` + `LAYER_OFF`)

**동작 규칙**
- 범례 제외는 **명시 규칙으로만** 한다. 자동 탐지는 `LEGEND_SUSPECT` 경고만 하고 수량은 바꾸지 않는다(D-009 Q9).
- 동결·끔 레이어는 기본으로 제외하되 목록에 남긴다. 규칙 파일 설정으로 포함하도록 바꿀 수 있다(D-009 Q3).
- **숨김 레이어 제외 건수 표시(D-009 Q3 조건)**: `LAYER_FROZEN` 또는 `LAYER_OFF`로 제외된 인스턴스가 1개 이상이면, 수량산출서 요약 시트 맨 위에 그 건수(사유별, 합계)를 표시한다(F-010). 0건이면 표시하지 않는다.
- 중복은 1개만 세고 나머지를 `DUPLICATE`로 제외하며 짝 handle을 기록한다. 허용오차 기본값은 **도면 단위 환산 1mm**이고 데이터 파일에 둔다. 실도면 기준선에서 재검토한다(D-009 Q2). 회전이 다른 중복은 제외하되 경고 문구에 회전 차이를 표기한다.
- 동결과 끔이 중첩 블록에서 AutoCAD 표시 규칙과 같게 동작하는지는 `cad-parser` 스파이크 확인 항목 (b)(D-012)로 확인한다. 다르면 이 규칙을 개정한다.

**검증 조건**
- [ ] T-10: 페이퍼스페이스 인스턴스가 정답 개수만큼 `PAPER_SPACE`로 제외되고, 모델스페이스 수량에 섞이지 않는다.
- [ ] T-09: 동결 레이어와 끔 레이어 인스턴스가 각각 정답 개수만큼 제외된다. 포함 설정을 켜면 수량이 정답(포함 시)과 일치한다.
- [ ] T-09: 수량산출서 요약 시트 맨 위에 숨김 레이어 제외 건수가 표시되고, 그 값이 `LAYER_FROZEN`·`LAYER_OFF` 제외 인스턴스 수(사유별, 합계)와 일치한다. 숨김 레이어가 없는 T-01에서는 표시가 없다.
- [ ] T-11: 허용오차 안의 중복은 `DUPLICATE`로 제외되고 짝 handle이 기록된다. 허용오차 밖(예: 50mm 떨어짐)은 둘 다 센다.
- [ ] T-12: 범례 영역을 지정하지 않으면 `LEGEND_SUSPECT` 경고가 1건 이상 나오고 수량은 범례 포함값 그대로다. 지정하면 범례 기호가 정답 개수만큼 `LEGEND_AREA`로 제외된다.
- [ ] 인스턴스마다 사유가 정확히 1개다(다중 사유 0).

**파이프라인 단계**: 2 물량산출 | **관련 결정**: D-004(a), D-009(Q2·Q3·Q9), operating-rules 규칙 2 | **저니**: 2, 3, 4

### F-007 매핑 규칙 파일

**한 줄 설명**: 사람이 편집하는 규칙 파일로 "어떤 레이어·블록·속성의 인스턴스가 어떤 품목인가"를 정한다.

**입력**: 규칙 파일(텍스트, 사람 편집용. 형식은 ADR에서 정하고, `repo-conventions.md`의 계획은 `data/mappings/<공종>_<대상>.yaml`), 품목 사전(F-008)

**처리**
1. 규칙 조건(AND로 결합): 블록 이름(정확 일치 또는 패턴), 원본 블록 이름, 유효 레이어(정확 일치 또는 패턴), ATTRIB 조건(키 = 값 또는 패턴), 적용 파일 범위(선택).
2. 규칙 결과: **품목 ID**(F-008) 또는 **IGNORE**(사유 텍스트 필수. 예: 방위표, 표제란 블록).
3. 규칙마다 ID와 정수 우선순위를 둔다. 높은 우선순위가 이긴다. 같은 우선순위에서 2개 이상 매칭되면 `CONFLICT`로 처리한다.
4. 규칙 옵션: `descend`(F-005 중첩 처리). 기본값은 꺼짐이다(매칭에서 탐색 정지, D-009 Q10).
   - `descend`가 꺼진 규칙에 매칭된 블록 안에 다른 규칙에 매칭될 자식이 있으면 F-005가 `NESTED_MATCH_HIDDEN`을 낸다. 이 경고는 규칙 ID 단위로도 집계해 "이 규칙이 숨긴 자식 n개"를 보여 준다. 담당자가 `descend`를 켤지, 부모 규칙(특히 IGNORE 래퍼)을 고칠지 판단하는 근거다.
5. 규칙 파일에 제외 설정 절(F-006)을 둔다.
6. 실행 전에 규칙 파일을 검증한다: 문법 오류, 품목 사전에 없는 품목 ID 참조, IGNORE 사유 누락.

**출력**: 인스턴스별 매칭 결과(규칙 ID, 품목 ID 또는 IGNORE/CONFLICT/UNMAPPED), 규칙 파일 해시, 한 번도 매칭되지 않은 규칙 목록, 규칙별 숨은 자식 수(`NESTED_MATCH_HIDDEN` 집계)

**동작 규칙**
- 매핑은 규칙 파일로만 정한다. 이름이 비슷하다는 이유로 자동 매칭하지 않는다.
- 규칙 파일 검증에 실패하면 수량을 내지 않는다(오류 메시지에 줄 번호 표시).
- 공종을 바꾸면(D-003) 이 파일과 품목 사전만 바뀐다.
- 규칙의 내용(조건, 결과, 우선순위, `descend`, 제외 설정)은 파일 형식과 독립적으로 정의한다. 사용 형태가 바뀌면(D-011, 예: xlsx 표 편집) 형식만 바뀐다. 형식은 ADR에서 정한다.
- 숨은 자식이 있다는 이유로 `descend`를 자동으로 켜지 않는다. 경고만 하고 판단은 담당자가 한다.

**검증 조건**
- [ ] T-05: 같은 블록이라도 ATTRIB 값(예: 와트수)에 따라 다른 품목으로 나뉘고, 각 개수가 정답과 일치한다.
- [ ] T-18: 같은 우선순위 규칙 2개가 매칭되는 인스턴스가 정답 개수만큼 `CONFLICT`로 나오고, 수량에는 0으로 반영된다(어느 품목에도 들어가지 않음).
- [ ] 존재하지 않는 품목 ID를 참조하는 규칙 파일로 실행하면 오류가 나고 수량 산출물이 0개 생성된다.
- [ ] 수량 행마다 적용 규칙 ID가 기록돼 있다(100%).
- [ ] 규칙만 바꿔 다시 실행하면 결과가 바뀐다(코드 변경 0). 합성 세트에서 규칙 1개를 수정하는 시나리오로 확인한다.
- [ ] T-03 IGNORE 래퍼 시나리오: 래퍼를 매칭한 IGNORE 규칙 ID의 숨은 자식 수가 정답과 일치한다. 그 규칙에 `descend`를 켜고 다시 실행하면 `NESTED_MATCH_HIDDEN`이 0건이 되고 래퍼 안 기구 수량이 정답과 일치한다(코드 변경 0).

**파이프라인 단계**: 2 물량산출 | **관련 결정**: D-003, D-009(Q10), D-011(Q1), C-5 | **저니**: 4

### F-008 품목 사전

**한 줄 설명**: 내부 품목 ID마다 품명, 규격, 단위, 공종을 정의한다. 조달청 표준공사코드는 참조 속성으로 붙인다.

**입력**: 품목 사전 데이터 파일, (선택) 조달청 표준공사코드 스냅샷(세부공종코드 15151273, 자원코드 15151393)

**처리**
1. 필드: 내부 품목 ID(고유), 품명, 규격, 단위(MVP는 EA), 공종, 참조 속성(조달청 세부공종코드, 자원코드. 비워 둘 수 있음), 비고, 데이터 구분(실무 / 합성용).
2. 로드할 때 검증한다: ID 중복, 단위 누락, 참조 코드가 스냅샷에 없는 값인지.

**출력**: 품목 사전(F-007, F-010, F-017, F-018에서 쓴다)

**동작 규칙**
- 표준공사코드는 내부 ID를 대체하지 않는다. 매핑되지 않은 품목은 코드를 비워 둔다(D-005).
- 에이전트는 실무 품목의 규격 목록을 지어내지 않는다. 합성 테스트용 품목은 "합성용"으로 표시하고, 실무 품목은 실도면·범례·사용자 자료로 채운다.

**검증 조건**
- [ ] ID 중복 0, 단위 누락 0인 사전만 로드된다. 위반 사전을 넣으면 로드 오류가 난다.
- [ ] 스냅샷에 없는 참조 코드를 넣은 테스트 사전에서 해당 항목 경고가 100% 탐지된다.
- [ ] "합성용" 품목이 실도면 실행 산출물에 나타나면 경고가 난다.

**파이프라인 단계**: 2 물량산출, 3 단가 | **관련 결정**: D-003, D-005(품목 키) | **저니**: 4

### F-009 귀속·UNMAPPED 보고

**한 줄 설명**: 모든 INSERT 인스턴스가 어디로 갔는지(매핑, 제외, 미매핑, 충돌) 빠짐없이 보여 주고, 그 합이 맞는지 확인한다.

**입력**: F-005~F-007 결과

**처리**
1. **귀속 등식**(파일별): 전개 후 INSERT 인스턴스 총수 = MAPPED + EXCLUDED(사유별 합) + UNMAPPED + CONFLICT.
2. **UNMAPPED 그룹**: (파일, 유효 레이어, 매핑 키, ATTRIB 요약)으로 묶어 개수, handle 목록, 대표 좌표를 낸다.
3. **비블록 기호 의심**: 매핑 규칙이 조건으로 참조하는 레이어(기구 레이어)에 있는 INSERT가 아닌 도형(CIRCLE, 닫힌 폴리라인, HATCH 등)을 `NON_BLOCK_SYMBOL` 경고로 낸다(개수, handle). 수량에는 넣지 않는다.
4. **집계 대상 외 요약**: INSERT가 아닌 엔티티를 유형·레이어별 개수로 요약한다.

**출력**: 귀속 요약표, UNMAPPED/CONFLICT 목록, `NON_BLOCK_SYMBOL` 경고, 집계 대상 외 요약

**동작 규칙**
- 귀속 등식이 성립하지 않으면 경고가 아니라 **실행 실패**로 처리하고 수량 산출물을 내지 않는다. 등식이 깨졌다는 것은 집계 로직 결함을 뜻한다.
- UNMAPPED가 0이 아니어도 수량산출서는 낸다. 요약 시트 맨 위에 "UNMAPPED n개(그룹 m개)"를 표시한다.

**검증 조건**
- [ ] 합성 세트 전 파일에서 귀속 등식 위반 0(S-3).
- [ ] 집계 결과에서 인스턴스 하나를 빼는 결함을 테스트로 주입하면 실행이 실패하고 산출물이 생성되지 않는다.
- [ ] T-16: 기구 레이어에 원으로 그린 기호가 정답 개수만큼 `NON_BLOCK_SYMBOL`로 보고되고 수량에는 0으로 반영된다.
- [ ] UNMAPPED 그룹의 개수 합 = UNMAPPED 인스턴스 수.

**파이프라인 단계**: 2 물량산출 | **관련 결정**: D-002(c), operating-rules 규칙 2 | **저니**: 3, 4

### F-014 UNMAPPED → 매핑 규칙 초안 내보내기

**한 줄 설명**: UNMAPPED 그룹을 규칙 파일 형식의 초안으로 내보낸다. 담당자는 품목 ID만 채우면 된다.

**입력**: F-009 UNMAPPED 그룹, 현재 규칙 파일

**처리**
1. UNMAPPED 그룹마다 조건(블록 이름, 유효 레이어, ATTRIB)이 채워진 규칙 초안 1개를 만든다. 품목 ID는 빈칸이다.
2. 주석에 개수, 예시 handle(최대 몇 개), 대표 좌표, 파일을 적는다. `*U` 이름이면 파일 범위 한정 경고를 넣는다.
3. 기존 규칙 파일과 겹치지 않는 새 파일로 저장한다.

**출력**: 규칙 초안 파일

**동작 규칙**
- 품목 ID를 자동으로 채우거나 추천하지 않는다(MVP). 추천은 2단계 후보다.
- 기존 규칙 파일을 덮어쓰지 않는다.
- 품목 ID가 빈 규칙은 로드할 때 비활성으로 처리하고 경고한다. 수량에 영향을 주지 않는다.

**검증 조건**
- [ ] 초안의 규칙 수 = UNMAPPED 그룹 수.
- [ ] 합성 시나리오에서 초안에 품목 ID를 채워 병합한 뒤 다시 실행하면 해당 그룹의 UNMAPPED가 0이 되고, 수량이 정답과 일치한다.
- [ ] 빈 품목 ID 초안을 그대로 로드하면 수량 변화가 0이고 경고가 나온다.
- [ ] 실행 전후 기존 규칙 파일의 해시가 같다.

**파이프라인 단계**: 2 물량산출 | **관련 결정**: D-001(담당자가 수정) | **저니**: 4

### F-010 수량산출서 xlsx 출력

**한 줄 설명**: 담당자가 검토하고 자기 내역서에 옮길 수 있는 수량산출서를 만든다. 수량 1EA마다 도면 근거 handle이 붙는다.

- [ ] 요약 시트의 `NESTED_MATCH_HIDDEN` 건수 = 경고 시트의 해당 코드 행 수(T-03).
- [ ] 생성 파일을 엑셀(또는 호환 프로그램)에서 열어 시트 7개가 보이는지 1회 수동 확인하고, 그 결과를 QA 리포트에 기록한다.

### F-015 자재 단가 스냅샷 적재 · 가격 소스 어댑터 인터페이스

**한 줄 설명**: 조달청 공공데이터 CSV를 출처 메타데이터와 함께 바꿀 수 없는 스냅샷으로 적재한다. 나중에 API로 바꿀 수 있게 가격 소스 공통 계약을 정의한다.

**입력**
| 항목 | 출처 | 필수 |
|---|---|---|
| 시설공통자재 가격정보 CSV | data.go.kr 15083244(수동 다운로드) | 필수 |
| 표준시장단가 CSV | data.go.kr 15151298(수동 다운로드) | 필수 |
| 표준공사코드 CSV(세부공종코드, 자원코드) | 15151273, 15151393 | 선택(F-008 참조 검증용) |
| 다운로드 메타: 다운로드 시각, 데이터셋 ID, URL, 페이지 표기 수정일 | 다운로드한 사람이 기록 | 필수 |

**처리**
1. CSV를 읽어 표준 단가 레코드로 바꾼다. 레코드마다 **D-005(a)의 7개 필드**를 붙인다: 출처 기관, 자료명, 데이터셋 ID 또는 URL, 게시일자·기준일, 다운로드 시각, `부가가치세포함여부`, 단위. 원본 행 번호와 CSV 해시도 함께 붙인다. 여기에 **출처 유형**(0절 단가 출처 유형) 필드를 필수로 둔다.
   - **`QUOTE` 예약(D-011)**: 표준 단가 레코드 스키마의 출처 유형 값 목록에 `QUOTE`(사용자 수기 단가, 업체 견적)를 처음부터 넣어 둔다. MVP에는 QUOTE를 만드는 입력 기능이 없다. QUOTE 레코드도 D-005(a) 7개 필드를 그대로 채울 수 있어야 한다(예: 출처 기관 = 업체명, 자료명 = 견적서명·번호, 기준일 = 견적일). 필드 대응의 세부와 추가 필드(유효기간 등)는 QUOTE 입력 기능 착수 시 정하되, **스키마 변경 없이 값만 추가**하는 범위로 한정한다.
2. 표준시장단가는 재료비, 노무비, 경비, 합계의 분리값을 그대로 보존한다.
3. 필수 필드가 빠진 행은 적재를 거부하고 거부 목록에 넣는다.
4. 스냅샷은 `data/prices/<출처>_<기준일>` 형태로 저장한 뒤 수정하지 않는다. 새 자료는 새 스냅샷으로 만든다.
5. **가격 소스 어댑터 계약**: "출처 → 표준 단가 레코드 목록 + 적재 리포트". CSV 어댑터를 구현한다. data.go.kr API 어댑터는 계약(입출력 정의)만 두고, 호출 코드는 사용자가 키를 발급할 때까지 만들지 않는다.

**출력**: 단가 스냅샷, 적재 리포트(원본 행 수, 적재 수, 거부 수와 사유)

**동작 규칙**
- 공식 출처만 받는다. 제3자 미러(pstatic 등)를 출처 URL로 하는 자료는 거부한다(D-005 c).
- `부가가치세포함여부`가 없는 행은 "VAT 미상"으로 표시한다. F-017에서 VAT가 확인된 단가와 합산하지 않는다(D-005 b).
- 스냅샷 생성 시 네트워크를 쓰지 않는다. 다운로드는 사람(또는 에이전트의 공개 페이지 조회)이 먼저 해 둔다(C-1).

**검증 조건**
- [ ] 적재 수 + 거부 수 = 원본 행 수(전 파일).
- [ ] 적재 레코드의 7개 필드 채움률 100%.
- [ ] `estimate-verifier` 표본: 무작위 20개 레코드의 가격·단위·VAT 필드가 원본 CSV 행과 일치한다(20/20).
- [ ] 같은 CSV를 다시 적재하면 스냅샷 내용이 같다(C-4).
- [ ] 미러 URL을 출처로 넣은 테스트 입력이 거부된다.
- [ ] 적재 레코드의 출처 유형 필드 채움률 100%.
- [ ] `QUOTE` 예약: 출처 유형이 `QUOTE`이고 7개 필드가 모두 채워진 테스트 레코드 1건이 레코드 스키마 검증을 통과한다(스키마 수정 0). MVP CSV 적재 경로에서 QUOTE 레코드가 생성되는 건수는 0이다.

**파이프라인 단계**: 3 단가·원가 | **관련 결정**: D-005, D-011(Q8) | **저니**: 6

**처리**

### F-017 단가 적용

**한 줄 설명**: 수량 품목에 재료비, 노무비, 경비 단가를 성분별로 붙인다. 출처로 되돌아갈 수 없는 성분은 UNPRICED로 남긴다.

**입력**: 수량 결과(F-010의 품목별 수량), 품목 사전(F-008), **품목-단가 연결 파일**(사람 편집. 성분별로 **출처 유형**(0절, `QUOTE` 예약 포함)과 그 유형의 레코드 키를 지정한다: 자재 단가 레코드 키 또는 표준시장단가 세부공종코드. 노무는 품셈 항목 출처, 직종, 투입인공), 자재 스냅샷(F-015), 노임 스냅샷(F-016)

**처리**
1. **재료비**: 연결된 자재 레코드의 가격을 쓴다. 수량 단위와 단가 단위가 다르면 그 성분을 UNPRICED로 두고 `UNIT_MISMATCH` 경고를 낸다.
2. **표준시장단가 연결 품목**: 레코드의 재료·노무·경비 분리값을 그대로 쓰고, 출처를 표준시장단가로 기록한다.
3. **노무비**: "품셈 투입인공(출처: 품셈명, 판, 항목 번호) × 노임(F-016)"으로 추적할 수 있을 때만 계산한다. 전기공사 표준품셈의 발행처와 이용조건이 확인되기 전에는 **전부 UNPRICED**로 두고 사유를 "전기공사 표준품셈 이용조건 미확인(D-005)"으로 적는다.
4. **경비**: 출처가 있는 경우만 계산한다. 출처가 없으면 UNPRICED이고, 0으로 두지 않는다. 출처가 "해당 없음"을 명시하면 NA로 둔다.
5. **할증**: 출처(품셈 판·항목)가 있는 할증률만 단가 단계에서 한 번 적용한다. 출처가 없으면 적용하지 않고 "할증 미확인"으로 표시한다. 수량 열은 순수량을 유지한다(operating-rules 규칙 4).
6. **금액** = 수량 × 성분 단가. 원 미만 처리(반올림·절사) 규칙은 출처를 확인한 뒤 데이터로 정의한다. 확인 전에는 계산값을 그대로 보존하고, 처리 규칙이 미정이라고 표시한다.
7. **상태**: 성분별 PRICED/UNPRICED/NA를 붙이고 STALE 플래그를 단다(기준일 1년 초과, 노임은 해당 반기 아님). 행 상태는 PRICED/PARTIAL/UNPRICED다.

**출력**: 단가 적용 결과(estimate.json에 해당)

**동작 규칙**
- 연결은 사람이 지정한 연결 파일로만 한다. 이름 유사도로 자동 연결하지 않고, 비슷한 품목으로 대체하지 않는다(D-005 d). 조달청 가격에 없는 브랜드 조명기구는 UNPRICED다.
- ESTIMATED(추정 단가)를 만드는 기능은 MVP에 없다.
- VAT 포함 단가와 미포함(또는 미상) 단가를 한 합계로 섞지 않는다(D-005 b).
- **`QUOTE` 예약(D-011)**: 연결 파일 스키마는 출처 유형 `QUOTE`를 유효한 값으로 받는다. QUOTE 입력 기능이 없는 MVP에서 QUOTE 연결이 있으면 해당 성분을 0이나 다른 출처로 채우지 않고 UNPRICED로 두며, 사유를 "QUOTE 입력 미지원 — 2단계(D-011)"로 적는다. 사용자가 질문 9에서 (c)를 고르면 QUOTE 입력이 M2로 앞당겨지고 이 규칙을 개정한다.

**검증 조건**
- [ ] UNPRICED 성분의 단가·금액 셀이 0이 아니라 빈칸과 표시로 나온다(출처 없는 0 셀 0건, S-8).
- [ ] 단위 불일치 테스트 품목이 100% UNPRICED와 `UNIT_MISMATCH`로 나온다.
- [ ] 노무비 성분이 전부 UNPRICED이고 사유 문구가 100% 기재돼 있다(전기 품셈 확인 전 상태).
- [ ] VAT 기준이 섞인 테스트에서 혼합 합계가 0건이다.
- [ ] `estimate-verifier` 표본 재계산: PRICED 성분 무작위 20개에서 금액 = 수량 × 단가가 일치하고, 단가가 스냅샷 레코드와 일치한다(20/20).
- [ ] 자재 단가 기준일이 실행일보다 1년 넘게 이전인 테스트 레코드가 STALE로 표시된다.
- [ ] `QUOTE` 예약: 출처 유형 `QUOTE`를 쓴 연결 행이 들어 있는 연결 파일이 스키마 검증을 통과하고(스키마 수정 0), 해당 성분이 100% UNPRICED와 "QUOTE 입력 미지원" 사유로 나온다(금액 셀 0 기입 0건).

**파이프라인 단계**: 3 단가·원가 | **관련 결정**: D-005, D-007, D-011(Q8), operating-rules 규칙 2·3·4 | **저니**: 6

### F-018 내역서 xlsx 출력 (직접공사비)

**한 줄 설명**: 재료비, 노무비, 경비를 분리한 공공 내역서 열 구조로 직접공사비 내역서를 만든다. 미확인 항목은 숨기지 않는다.

**입력**: F-017 결과, F-010 수량산출서(행 참조용)

**처리**
1. **내역서 시트 열**(D-007, 출력 양식 v1: D-008 Q4): 번호, 품목 ID, 품명, 규격, 단위, 수량, 재료비 단가·금액, 노무비 단가·금액, 경비 단가·금액, 합계 단가·금액, 성분별 상태, 단가 출처(성분별: 기관, 자료명, 기준일, 데이터셋 ID 또는 URL), VAT 포함 여부, 표준공사코드(참조), 도면 근거(수량산출서 행 참조, 근거 handle 수), 비고(UNPRICED 사유, STALE, 할증 미확인).
2. **하단 소계**: 직접공사비 소계는 PRICED 성분만 합산한다. "미확인: 재료 n품목 / 노무 m품목 / 경비 k품목", STALE 건수를 함께 표시한다. VAT 기준이 다른 단가가 있으면 기준별로 소계를 따로 낸다.
3. **부속 시트**: 단가 출처 목록(사용한 스냅샷과 레코드), 미확인 목록, 실행정보.

**출력**: `내역서.xlsx`(수량산출서와 같은 출력 폴더)

**동작 규칙**
- 원가계산서 시트(간접공사비, 일반관리비, 이윤)는 만들지 않는다(D-007).
- 미확인 성분이 하나라도 있으면 소계 셀 옆에 "불완전 합계"를 표기한다.
- 민간 실행견적 사용자는 열을 합쳐 쓰면 된다. 열을 합친 버전은 만들지 않는다(D-007).
- 초안 문구(C-6)를 넣는다.

**검증 조건**
- [ ] 내역서 수량 = 수량산출서 요약 수량(품목별 100%).
- [ ] 소계 = PRICED 성분 금액 합계(독립 재계산 일치).
- [ ] 미확인 개수 표시 = 실제 UNPRICED 성분 수.
- [ ] PRICED 성분의 출처 필드 누락 0(S-7).
- [ ] 원가계산서 시트 0개.
- [ ] 미확인이 있는 테스트 세트에서 "불완전 합계" 표기가 있다.

**파이프라인 단계**: 3 단가·원가 → 출력 | **관련 결정**: D-007, D-005 | **저니**: 6, 7

### F-019 원가계산서 · 제비율 파라미터 — **보류 (D-007: 견적 방식 확정 후)**

**한 줄 설명**: 견적 방식이 확정되면 사용자가 입력한 제비율(근거 포함)로 원가계산서를 만든다. 지금은 범위만 정의한다.

**입력(예정)**: 제비율 파라미터 파일. 항목은 간접노무비율, 기타경비율, 산재·고용보험료율, 산업안전보건관리비, 일반관리비율, 이윤율 등이다. 값마다 근거(고시·예규명, 판·개정일, 적용 기준일, 사내 기준 여부)를 함께 받는다.

- 상한 규정 경고(일반관리비·이윤 상한 등)는 공식 원문을 확인한 뒤에만 추가한다.

**검증 조건(착수 시 적용)**
- [ ] 기본값이 0개다(빈 파라미터 파일로 실행하면 모든 원가 항목이 "제비율 미입력").
- [ ] 근거가 빠진 값은 100% 거부된다.
- [ ] 미입력 항목의 계산 결과 셀이 0이 아니라 표시로 나온다.

**파이프라인 단계**: 3 단가·원가 | **관련 결정**: D-006, D-007 | **착수 조건**: 사용자 답변(견적 방식) → CEO 재판정

### F-012 합성 DXF 생성기 · 골든 정답

**한 줄 설명**: 정답 개수를 알고 있는 합성 DXF 세트를 함정 케이스까지 포함해 재현 가능하게 생성한다. 실도면 확보 전 회귀 테스트의 기준이다.

**입력**: 생성 파라미터(케이스 목록, 시드), 합성용 품목 사전·매핑 규칙

**처리**
1. 아래 함정 목록의 케이스를 DXF로 생성한다.
2. 정답 파일을 **생성 파라미터에서 계산해** 함께 쓴다. 정답에는 (품목, 파일)별 수량, 제외 사유별 개수와 handle, 숨김 레이어 제외 건수, 기대 경고 코드와 handle(`NESTED_MATCH_HIDDEN`의 부모 handle 경로·숨은 자식 개수, `UNIT_USER_SET`·`UNIT_OVERRIDE` 포함), 기대 UNMAPPED·CONFLICT, 귀속 등식 값이 들어간다.
3. 저장 위치는 `data/drawings/samples/synthetic/` 또는 tests 아래로 한다(D-004 a, ADR에서 확정).

**착수 조건(D-012)**
- 지금 착수할 수 있다. 다만 **정답 파일 형식과 합성용 규칙·사전 형식은 ADR 확정 전까지 잠정**이다.
- ADR 승인 전 잠정 형식 골든으로 돌린 회귀 결과는 **M1 완료 판정에 쓰지 않는다**. M1 판정용 골든은 ADR 승인 후 확정 형식으로 다시 생성한 것만 인정한다.
- 생성기 작성자와 집계 구현자가 같은 에이전트 세션이면 `estimate-verifier`가 정답 계산을 독립 검토한다.
- 스파이크(`spikes/`)는 이 생성기의 DXF와 ezdxf 예제 DXF(MIT)만 입력으로 쓴다. 실도면은 쓰지 않는다.

- 합성 결과를 쓰는 모든 산출물과 리포트에 "자기 일관성 검증 — 실제 정확도 아님"을 표시한다(D-004 조건).

- [ ] 생성된 DXF가 파서 구조 검사(audit)에서 오류 0이다(T-20 손상 파일 제외).

### F-013 정확도 평가 리포트

**한 줄 설명**: 집계 결과를 정답(합성 골든 또는 실도면 정답표)과 비교해 성공 지표를 계산한다.

**입력**: 집계·내역서 결과, 정답. 합성이면 F-012 정답 파일, 실도면이면 정규화 정답표(품목 ID – 파일 – 수량 – 원문 행 번호, 할증 포함 여부 플래그).

**처리**
1. 합성이면 S-1~S-5를 계산한다. 실도면이면 R-1~R-4, R-8, R-9를 계산한다(정의는 기획 문서 5절).
2. 품목별 차이표를 만든다: 정답, 결과, 차이, 원인 분류 칸(담당자나 verifier가 기입. 분류 예: 매핑 누락, 범례 미제외, 정답 측 오류, 도면 외 품목).
3. 정답 품목 중 MVP 공종 범위 밖 품목은 재현율 분모에서 빼고, 개수를 따로 표시한다.

**출력**: 평가 리포트(`output/` 아래). `estimate-verifier`는 이를 입력으로 `docs/qa/`에 독립 검증 리포트를 쓴다.

**동작 규칙**
- 합성 리포트 머리에는 "자기 일관성 검증 — 실제 정확도 아님" 문구를 고정한다.
- 정답이 할증 포함으로 표시돼 있으면 R-3, R-4는 "비교 불가"로 표시하고 계산하지 않는다.
- 실도면 정답표 옮겨 적기는 담당자가 확인한 것만 쓴다. 정답표 파일 해시를 리포트에 기록한다.

**검증 조건**
- [ ] 손으로 계산한 소형 예제(품목 3개, 오차 포함)에서 리포트의 지표값이 기대값과 일치한다(재현율, 정밀도, 오차율 모두).
- [ ] 합성 리포트에 고정 문구가 있다.
- [ ] 할증 포함 플래그 입력에서 R-3, R-4가 "비교 불가"로 나온다.
- [ ] 공종 범위 밖 정답 품목이 분모에서 빠지고 별도로 표시된다.

**파이프라인 단계**: 4 검증 | **관련 결정**: D-001, D-004 | **마일스톤**: M1(합성), M3(실도면)
