## D-002 2026-11-09 MVP 입력 처리 경로 (Gate 2)

- 질의자: 메인 세션(리서치 루프)
- 판정: APPROVE (조건부, 일부는 사용자 확인 대기)
- 결정: 조사 1안 채택, 2안(IFC 우선)은 반려. 코어는 **DXF + ezdxf(MIT)**. DWG 변환은 코어 밖의 교체 가능한 전처리 어댑터로 둔다. **ODA File Converter는 기본 경로로 두지 않는다.** 적용 순서는 다음과 같다.
  1. MVP 기본 경로: 사용자가 자기 CAD에서 **DXF로 저장해 제공**한다. 라이선스 리스크가 없고 원본 엔진으로 변환된다.
  2. 사용자가 AutoCAD/BricsCAD 보유를 확인하면, 그 프로그램의 로컬 자동 변환(accoreconsole 스크립트, BricsCAD /automation)을 선택형 어댑터로 추가한다.
  3. ODA File Converter는 사용자가 업무 사용 가능 여부를 판단·수용한 뒤에만 선택형 어댑터로 쓴다. 그 전에는 개발 PC에도 설치·실행하지 않는다.
  - LibreDWG는 MVP에서 제외한다(GPL 문제, R2010 이상에서 엔티티 누락 시 물량 누락으로 이어짐). ODA SDK·Aspose 같은 유료 수단은 사용자 승인 사항이다.
  - IFC(IfcOpenShell)와 RVT는 MVP에서 제외하고 2단계 후보로 둔다.
- 조건:
  - (a) 파서 출력은 포맷 중립 정규화 레코드로 한다. 각 레코드에는 원본 파일, 레이어, 블록명, handle, 단위를 붙인다. 이렇게 해야 IFC 어댑터를 나중에 붙일 수 있다.
  - (b) 변환을 거친 입력은 변환 이력을 기록한다(변환기명·버전, 원본 해시, DXF 해시).
  - (c) XREF, 동적 블록(`*U` 익명 블록), ACIS, UNDERLAY처럼 ezdxf가 처리하지 못하는 요소는 조용히 무시하지 않는다. 경고 목록으로 출력한다.
  - (d) `$INSUNITS`가 없거나 0이면 수량을 내지 않고 단위 확인 필요로 표시한다.
- 근거:
  - docs/research/2026-11-09_drawing-input-tools.md에 따르면 ezdxf는 MIT 라이선스이고 1.4.5에서 Python 3.14를 명시한다.
  - ODA FAQ는 비회원 사용을 non-commercial로 한정한다. 업무 사용 약관은 미확인이다.
  - 한국 실무는 DWG/PDF 중심이라는 정황이 있다(2차 근거).
  - 원칙 2(좁은 MVP)와 원칙 3(로컬·무료)에 맞는다.
- 사용자 확인 대기: DWG 버전과 실제 수령 포맷, AutoCAD/BricsCAD 보유 여부, ODA 업무 사용 수용 여부.
- 되돌리기 비용: 낮음~중간. 변환은 어댑터로 분리돼 있고, 코어(ezdxf)를 교체할 가능성은 낮다.
